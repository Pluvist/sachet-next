# 登录会话恢复修复

## 行为

使用学号、密码登录并勾选“记住密码”后，应用先完成加密保存，再通知主页开始更新。重进应用时，查询等待账号恢复；教务系统会话过期则使用已记住的密码静默重新登录，保存新会话并将原查询重试一次。

同一账号的并发查询共享一次重新登录。超时、断网、普通权限错误不会触发重复登录，也不会清除本地课表缓存。显式退出或更换账号会阻止旧请求覆盖新账号。未记住密码、密码已改变或服务器要求额外验证时，仍需手动登录。

## 修改原因

原实现中，登录状态通知可能早于密码保存；请求也可能在加密数据恢复前使用旧 Cookie。多个查询分别处理会话过期，会发起互相竞争的登录。分散的存储字段和异步删除还可能在中断时留下不一致的数据。登录网络流程另有自动跟随重定向、遗漏 Cookie 更新及未识别 HTTP 200 登录页的情况。

现在使用同一个安全存储中的加密账号快照作为恢复依据，串行提交相关操作。首次读取会迁移已有字段，无需删除应用数据。退出先写入空快照，再清理旧字段，防止清理中断恢复出已退出的账号。取消记住密码后不再保存密码；切换到其他账号的 Cookie 登录也不会继承之前的密码。

## 验证

- 249 项 Flutter 测试通过，静态分析无问题。测试使用虚构账号、密码和本地模拟网络，不依赖真实账户。
- 覆盖完整链路：冷启动读取旧凭据、三个请求同时遇到失效、只进行一次登录、重试查询、保存新会话、再次启动读取新会话。
- 覆盖存储延迟或失败、重复记住相同密码、账号切换、旧登录响应迟到、退出清理中断、记住密码选择、登录成功返回和失败重试。
- 登录传输测试覆盖初始化重定向、CSRF、Cookie 轮换、可选路由 Cookie、错误登录返回及重定向目的地校验。
- 针对 next.1 的真机反馈，兼容其他内部落地地址、带 URL 会话参数的路径和 HTTP 200 页面；通过已有的受保护个人信息接口确认会话。覆盖无身份页面、登录表单、Cookie 删除、验证服务故障和跨站跳转，验证过程不重放密码提交。

尚未使用真实教务账号在手机上验证。真机检查时应覆盖：登录并记住密码后划掉应用重开、保留后台后重新进入、离线重开后恢复网络、会话自然过期后查询、显式退出再重开。若旧版实际未保存密码，需要先重新登录并勾选一次“记住密码”。

修复先经 `0.19.75-next.1` 至 `next.3` 验证；正式版为 `0.19.75`，内部版本号 `46`，使用相同包名与发布签名。
